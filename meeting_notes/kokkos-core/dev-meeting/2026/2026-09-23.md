    - Discuss the naming and the need for these 3 new methods

    - this is actually an API change.
    - No known use in Trilinos.
    - Do we deprecate this? It's in experimental.
    - `lower`/`upper` vs `begin`/`end` discussed in the chat
- (RESOLVED) HIP: ParallelFor block size problem for register-hungry kernels: https://github.com/kokkos/kokkos/issues/9402
    - we want this, need some performance testing
- Update on [Issue #9477](https://github.com/kokkos/kokkos/issues/9477) Signedness of word size type used in CUDA and HIP reductions changes with the size of reduced variable
- Update on [Issue #9457](https://github.com/kokkos/kokkos/issues/9457) Should `std::tuple_{size,element}` be specialized for `Kokkos::pair`?
- (RESOLVED) Support for `std::float16_t`, `std::bfloat16_t` and even `std::float128_t` by compilers since it is part of C++23 and how that leads to proper implementation of `Kokkos::Experimental::half_t` without aliasing `float` on Host. See [PR #9253](https://github.com/kokkos/kokkos/pull/9253)
    - we want this  
- (RESOLVED) [PR #9542](https://github.com/kokkos/kokkos/pull/9542) Add an option to disable CUDA constant memory dispatch; add CUPTI-based tests to check that various expected launch types are used
    - Includes and supersedes [PR #9352](https://github.com/kokkos/kokkos/pull/9352) Add an option to disable CUDA constant memory dispatch
    - We used to consume 2/3 of the constant memory, making it hard for others to use it, so we removed it
    - re-added it when a user reported a regression
    - turns out to be a codegen corner case, and user has a workaround
    - we will remove this
- (RESOLVED) Allow kernels requiring a block size smaller than warp size: https://github.com/kokkos/kokkos/pull/9339
    - needs Carl's review
- (RESOLVED) Support Sacado for GPU backends: https://github.com/kokkos/kokkos/issues/9565
    - Sacado here straying outside the programming model. To what extent do we want to support this?
    - What do we do on the host?
    - Don't expose vector lane in the team handle, because we can't define a sensible value for host backends.
    - We will try this in SYCL, and see how easy it is. If it becomes a complicated re-engineering thing, we can perhaps discuss with Sacado.
    - It may be unreasonable for us to forever reserve a launch dimension in our internals purely for Sacado. No known other users.
- Revisit GitHub actions quick fix: https://github.com/kokkos/kokkos/pull/9562
- (RESOLVED) Remove Clacc support: https://github.com/kokkos/kokkos/pull/9570#discussion_r4073591271
    - no longer supported, not aware of any users, will removed
